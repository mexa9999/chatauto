# CitySim: нейроэволюция стратегий застройщиков

Мультиагентная модель города на NumPy: застройщики видят карту и принимают
решения о типе и качестве зданий, а нейроэволюция ищет стратегии, максимизирующие
прибыль при ограничениях на качество города и экстерналии.
Все политики могут сносить собственные здания; нейросеть использует для этого
обучаемый выход, а старые геномы загружаются с отключённым выходом сноса.
Обучаемая политика использует per-cell GRU с состоянием на эпизод и общий
городской бонус fitness (0.15 × среднее качества города и удовлетворённости).
PNG и live-карты по умолчанию изометрические; `--projection top-down` включает
прежнюю проекцию. Старые геномы до GRU и геномы до сноса поддерживаются.

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Быстрый запуск

```powershell
.\.venv\Scripts\python.exe -m citysim demo --quick --policy manual --out runs/demo
.\.venv\Scripts\python.exe -m citysim train --quick --out runs/train_quick
.\.venv\Scripts\python.exe -m citysim experiment e1 --quick --out runs/e1_quick
```

## Единое хранилище проекта: обучение, кеш и возобновление

Обучения с одинаковыми конфигурациями города и эволюции используют общий
SQLite-каталог `runs/.citysim-history` независимо от `--out`. Обычные
`train`-запуски сохраняют туда ветки и снимки, а E1–E12 — контрольные точки
обучений для повторного использования и возобновления. Поэтому `experiment all`
не переобучает модель с тем же сидом и параметрами. В базе хранятся ссылки на
неизменяемые контрольные точки с полной популяцией, а не только лучший геном.
Выходные таблицы и графики по-прежнему создаются в каталоге `--out`.

Контрольная точка записывается атомарно каждые 10 поколений по умолчанию.
После `Ctrl+C` или перезапуска компьютера повторите ту же команду с `--resume`:

```powershell
.\.venv\Scripts\python.exe -m citysim experiment all --seeds 0-29 --generations 500 --episodes 20 --population 64 --eval-seeds 20 --workers 16 --out runs/super-training --resume
```

Для более частых сохранений задайте `--checkpoint-every 1`; при внезапном
отключении будет потеряно не более `N-1` поколений (для значения по умолчанию —
максимум 9). Каталог можно переопределить параметром `--history-dir` (для
`experiment` также сохранён старый псевдоним `--cache-dir`); укажите один и тот
же путь в командах обучения и панели, если используете нестандартный каталог.
Хранилище содержит полные контрольные точки, поэтому ему может потребоваться
несколько гигабайт. Они привязаны к полной конфигурации: для возобновления
незавершённого обучения используйте `--resume` и те же параметры. Незавершённое
оценивание после готового обучения может быть повторено, но само обучение
загрузится из кеша.

## История обучения: ветки и откаты

Команда `train` хранит неизменяемые снимки популяции и историю веток в общей
базе проекта `runs/.citysim-history/history.sqlite3`. Это значение по умолчанию
для обучения, экспериментов, команд `history` и панели. Посмотреть ветки и
историю можно так:

```powershell
.\.venv\Scripts\python.exe -m citysim history branches
.\.venv\Scripts\python.exe -m citysim history log --branch main
```

Создайте ветку от сохранённого поколения и продолжите обучение с изменёнными
параметрами:

```powershell
.\.venv\Scripts\python.exe -m citysim history branch-create experiment --from main@40
.\.venv\Scripts\python.exe -m citysim train --out runs/train --branch experiment --resume --generations 200 --mutation-sigma 0.08
```

При продолжении можно менять город, сид и параметры эволюции, но не архитектуру
сети или размер популяции. При смене города популяция переоценивается в новом
мире. Ссылка `branch@N` доступна только для сохранённых поколений: по умолчанию
это каждое десятое поколение и финальный снимок; используйте
`--checkpoint-every 1`, если нужны точки после каждого поколения.

Откат перемещает указатель ветки, не удаляя более новые снимки:

```powershell
.\.venv\Scripts\python.exe -m citysim history reset experiment --to main@20
```

`experiment` сохраняет контрольные точки в той же базе и общем объектном
хранилище; они не становятся ветками обучения, но участвуют в проверке
целостности и защищены от очистки используемых снимков.

## Веб-панель экспериментов

Установите зависимости из `requirements.txt`, затем запустите панель:

```powershell
.\.venv\Scripts\python.exe -m citysim dashboard
```

Панель откроется в браузере и слушает только `127.0.0.1`. В ней можно
просматривать ветки и снимки, создавать/перемещать ветки, сравнивать любые два
снимка, проверять историю и очищать недостижимые снимки. Сравнение использует
общие тестовые сиды (по умолчанию пять), город из выбранного эталонного снимка
и оба режима: однородный город и лигу с фиксированными базовыми стратегиями.
Результат включает интервалы доверия, разницу метрик и отличия конфигураций.

В панели доступны демо симуляции, обучение по веткам, эксперименты E1–E12,
история снимков, сравнение моделей и обслуживание хранилища. Worker работает
отдельным процессом; прогресс и логи доступны в панели.

Интерфейс использует тему «тёмная лаборатория»: графитовый фон `#0b1013`,
поверхности `#141c21`, фиолетовый акцент `#6600ff`, коралловый `#e55137`,
оранжевый `#ff4f00` и голубой для успешных состояний. Схема города на главной нарисована встроенным SVG в
`webapp/src/App.tsx`, поэтому не требует внешних изображений или сетевого
доступа; её можно заменить локальным SVG-файлом в этом hero-блоке.

Демо можно смотреть в браузере в реальном времени: выберите встроенную
стратегию или снимок нейросети из истории обучения, затем управляйте скоростью,
паузой и остановкой. Карта отображается в изометрии. Панель не сохраняет PNG
для каждого хода: в `runs/.dashboard/jobs/<id>/artifacts/frames.jsonl`
сохраняются сжатые состояния карты после действий. После прогона кадры можно
листать, а выбранный при необходимости отрендерить и скачать как PNG из панели.
Данные входят в ZIP-экспорт запуска.

Число раундов на эпизод задаётся в форме запуска для демо, обучения и
экспериментов. По умолчанию быстрый режим использует 6 раундов, обычный — 20;
введённое вручную значение применяется в обоих режимах. Состояние запущенной
задачи, прогресс, остановка и журнал ошибки доступны в общей панели задач.

Запуски можно экспортировать в ZIP двух типов: легкий содержит результаты и
параметры, полный также содержит базу истории и контрольные точки. На другом
компьютере архив проверяется перед импортом; при совпадении можно пропустить,
переименовать или заменить набор. Полную импортированную историю можно открыть
в панели и продолжить обучение. Импортированные наборы хранятся отдельно, без
слияния веток с другими компьютерами.

На вкладке «Аналитика» можно сравнить до четырёх локальных и импортированных
запусков, отфильтровать раунды и агента, изучить метрики, распределения и
обучение. Журналы действий и раундов сохраняются в артефактах запуска
(`actions.ndjson`, `rounds.ndjson`, `analytics_summary.json`); для обучения
дополнительно сохраняются метрики поколений и отдельный полный журнал финальной
оценки. Таблицы выгружаются в CSV/JSON, графики — в PNG.

CLI и панель используют новое хранилище `runs/.citysim-history`. Данные из прежнего
`runs/.training-history` автоматически не переносятся и остаются нетронутыми;
для старой базы передайте ее путь через `--history-dir`.

Для разработки frontend:

```powershell
npm install --prefix webapp
npm run build --prefix webapp
```

Сборка React/TypeScript сохраняется в `citysim/web/build` и включается в
устанавливаемый пакет. Логи задач сохраняются в
`runs/train/.dashboard/jobs/<id>/training.log`.

Остановка запрашивается после текущего поколения и принудительного сохранения
снимка; затем незавершённое обучение можно возобновить с теми же параметрами.
Для очистки сначала сформируйте предпросмотр; фактическое удаление требует
отдельного подтверждения, а изменившаяся после предпросмотра история отменяет
операцию.

## Структура

- `citysim/` — модель, политики, эволюция, эксперименты и визуализация;
- `tests/` — smoke- и unit-тесты;
- `docs/` — формальное описание модели и литература;
- `runs/` — сгенерированные артефакты (не коммитятся).

Раннеры экспериментов сгруппированы в `citysim/experiments_learning.py`
(E1–E2), `citysim/experiments_sweeps.py` (E3–E8) и
`citysim/experiments_robustness.py` (E9–E11). Факторная абляция расширенных
действий и районной синергии E12 находится в `citysim/experiments_actions.py`.
Модуль
`citysim/experiments.py` сохраняет общий API для CLI и внешних импортов.
